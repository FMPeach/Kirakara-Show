# KRL / LRC 格式

Kirakara Show 读取 UTF-8 文本。普通 LRC 可以只包含歌词；KRL 在歌词前增加一个可选的
`config { ... }` JSON 对象，用于携带渲染配置和标题块。

```text
config {
  "fontSize": 62,
  "line1Y": 450
}

[00:10:00]歌[00:10:50]詞[00:11:00]
```

载入 KRL 时，Show 会自动读取 `config`，再解析后面的歌词。未知且不含时间戳的元数据行会被
忽略。

## 时间戳与逐字时序

时间戳采用 `[分:秒:小数]` 或 `[分:秒.小数]`。小数位按十进制解释，例如：

- `[00:00:17]` 是 `0.17` 秒；
- `[02:46:03]` 是 `166.03` 秒。

两个时间戳之间的文字构成一个时序段。若段中包含多个 Unicode 字符，持续时间会平均分配：

```text
[01:31:54]ビィ[01:31:77]
```

此时 `ビ` 与 `ィ` 各占一半。相邻时间戳之间没有文字时表示停顿。行尾有时间戳时，它是明确的
结束时间；没有时，解析器先补 500 ms，并可能在与下一行间隔小于 5 秒时延长到下一行。

渲染进度由媒体时间直接求值，不依赖已经显示了多少帧。

## 角色

角色标记使用全角书名括号和一个 `@`：

```text
【@miku】[00:10:00]独唱[00:11:00]
【@miku+rin】[00:12:00]合唱[00:13:00]
```

标记可以位于行首或行中，角色会向后继承，直到下一个显式标记。`+` 表示同一段文字由多个角色
共同演唱。没有 `@` 的 `【文字】` 是普通歌词，不会触发角色分色。

角色颜色、标签和图片由 `characterProfiles` 配置，见 [配置参考](config-reference.md)。

## 行内注音

主字、上方注音和下方注音写在同一组中：

```text
{主字|うえ}
{主字|うえ>した}
```

注音内部可以携带独立时间戳：

```text
{空|[02:41:26]か[02:41:43]ら>[02:41:26]ka[02:41:43]ra}
```

- 上方注音按字符时序推进；一段内含多个字符时会按字符均分该段时间。
- 下方注音按 token 时序推进，保留诸如 `shi`、`kyo` 这样的整体 token。
- 有注音时间时，主字组的走字优先由注音驱动；主字内部用于排版的时间标签不会再拆开注音
  连接的主字组。
- 主字中的时间标签不会作为可见字符。例如
  `{貴[02:46:68]方|[02:46:03]あ[02:46:36]な[02:46:68]た}` 的主字仍是 `貴方`。

## 独立 Ruby 表

也可以在歌词前提供 Ruby 字典：

```text
@Ruby35=歩夢,あ[00:00:17]ゆ[00:00:27]む
@Ruby23=合,あ,[00:53:33],[00:54:43]
```

注音时间是匹配主字组内部的偏移。可选的绝对时间范围用于限定匹配位置。解析时优先匹配较长的
主字 key，再回退到单字，从而保留共享注音跨度。

## 无时序参考歌词

`apply_lyric_reference()` 可以把另一份无时序歌词上的注音合并到已解析文档：

```text
ただ　{静|しず}かに
```

匹配会忽略空白并保持行序，只转移注音范围，不新增或修改播放时间。

## 标题

标题配置位于 `config.songTitle`：

```json
{
  "songTitle": {
    "enabled": true,
    "durationSec": 5,
    "textFade": true,
    "groups": [
      {
        "value": "曲名",
        "style": {"fontSize": 72, "align": "center"}
      },
      {
        "rows": [
          {"before": "歌手", "separator": "：", "after": "Kirakara"}
        ]
      }
    ]
  }
}
```

`value`、`lines` 和 `rows` 都可以提供标题文字；`kind`、`name`、`id` 等编辑器信息不会影响
显示效果。标题显示在普通媒体时间 `[0, durationSec)`，不会把播放时间轴向前延长。

`enabled: true` 且内容为空是合法的 no-op：标题模块照常初始化，但不绘制内容。为兼容编辑器，
`prelude.backgroundImage` 可以存在于文件中；当前引擎会忽略并跳过其 base64，不解码图片，也不
改变媒体时间。

## 其他元数据

- `role { ... }` 项目块会在进入 LRC 解析前移除；实际角色样式来自已归一化的配置。
- `@Emoji` 当前不参与 Kirakara Player 兼容解析。
- 配置字段和默认值见 [配置参考](config-reference.md)。
